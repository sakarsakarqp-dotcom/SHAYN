# شين | SHAYN — حزمة البداية المتكاملة

هذه حزمة مشروع Full-stack قابلة للتشغيل محلياً والنشر على استضافة تدعم Node.js وPostgreSQL. تتضمن واجهة عربية RTL، واجهات API، تسجيل حسابات، صلاحيات، إعلانات الوظائف والمشاريع والخدمات والسوق، التقديم على الإعلانات، الرسائل، التقييمات، البلاغات، ولوحة إدارة أولية.

## ما الذي يعمل في هذه الحزمة؟
- واجهة رئيسية متجاوبة وأقسام شين الستة.
- إنشاء حساب وتسجيل دخول باستخدام bcrypt وJWT.
- نشر واستعراض أربعة أنواع من الإعلانات: وظيفة، مشروع، خدمة، وسوق.
- تقديم المستخدم على إعلان، وإرسال الرسائل، وإضافة تقييم أو بلاغ عبر API.
- لوحة إحصاءات للمدير/المشرف وإدارة حالة الإعلانات وتغيير أدوار المستخدمين عبر API.
- مخطط PostgreSQL وفهارس أساسية.
- دور مستقل للمدير الأعلى `super_admin` مع حصر تغيير أدوار الحسابات به.
- قراءة الدور وحالة تفعيل الحساب من قاعدة البيانات عند كل طلب محمي، حتى لا تبقى صلاحية قديمة داخل JWT بعد سحبها.
- ترحيل قاعدة بيانات قابل لإعادة التشغيل لإضافة حالة الحساب ودور المدير الأعلى.

## متطلبات التشغيل
- Node.js 20 أو أحدث.
- قاعدة بيانات PostgreSQL.

## التشغيل محلياً
1. انسخ `.env.example` إلى ملف باسم `.env`.
2. أدخل `DATABASE_URL` الصحيح.
3. اختر كلمة مرور قوية في `ADMIN_PASSWORD`، وغيّر `JWT_SECRET` إلى قيمة عشوائية طويلة.
4. نفّذ:

```bash
npm install
npm run db:init
npm start
```

5. افتح `http://localhost:3000`.

لا ترفع ملف `.env` إلى GitHub ولا ترسل كلمات المرور أو مفاتيح الاتصال في المحادثات.

## النشر
ارفع ملفات المشروع إلى مستودع خاص، أنشئ PostgreSQL مُدارة، ثم أنشئ خدمة Node على منصة استضافة تدعم Node.js. أضف متغيرات البيئة (`DATABASE_URL`, `JWT_SECRET`, `ADMIN_PASSWORD`, `ADMIN_EMAIL`, `ADMIN_NAME`) وشغّل `npm run db:init` مرة واحدة، ثم أمر التشغيل `npm start`.

## ملاحظات مهمة قبل الإطلاق العام
هذه نسخة تأسيسية عاملة وليست بعدُ خدمة إنتاجية مكتملة أو مدققة أمنياً. قبل استقبال مستخدمين حقيقيين، يلزم استكمال واختبار: استعادة كلمة المرور والتحقق من البريد، تحديد معدل الطلبات، رفع الصور والملفات وتخزينها، صفحات تفاصيل المستخدم، سير عمل الدفع/العمولات إن لزم، سياسات الخصوصية والشروط، أدوات مراجعة المحتوى، حماية الرسائل من الإساءة، اختبارات آلية، النسخ الاحتياطي ومراقبة الأخطاء. كذلك يلزم اختبار صلاحيات كل endpoint ونشر نسخة تجريبية قبل الإطلاق.

## API مختصر
- `GET /api/health`
- `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/me`
- `GET /api/listings?type=job|project|service|market&q=...`
- `POST /api/listings` (يتطلب Bearer token)
- `POST /api/listings/:id/apply`
- `POST /api/messages`, `GET /api/messages`
- `POST /api/reviews`, `POST /api/reports`
- `GET /api/admin/overview`, `GET /api/admin/listings`, `PATCH /api/admin/listings/:id`, `GET /api/admin/reports`, `PATCH /api/admin/users/:id/role`


## دليل التصنيفات الموسع
تتضمن هذه النسخة دليلاً أولياً يضم 30 مجالاً رئيسياً و360 تصنيفاً فرعياً (390 عقدة تصنيف إجمالاً). يمكن جلبه من `GET /api/categories`، كما يظهر في دليل قابل للبحث ضمن الصفحة الرئيسية. هذه تصنيفات تأسيسية قابلة للتعديل وليست دليلاً نهائياً لكل سوق أو دولة.
